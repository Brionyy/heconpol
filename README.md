# 보건정치경제연구실 홈페이지(heconpol.org)

서울대학교 보건대학원 보건정치경제연구실 홈페이지의 원본입니다. 누구나 보는 화면은 이 폴더의 표 · 글로 만들고, 회원 칸은 로그인 서비스(Supabase, 서울 서버)가 맡습니다.

> 이 폴더는 **공개 저장소**가 됩니다. 회원 글 · 사진 · 메일, 업체에서 받은 DB, 비밀 열쇠는 절대 넣지 않습니다(`.gitignore`가 막는 목록).

## 관리 화면(조교, 2026-10-28)

회원 칸 `/lab/admin/`에서 단추 · 칸으로 고칩니다. 조교가 바뀌어도 GitHub · 표 파일을 몰라도 되게 만들었습니다. 탭마다 맨 위에 '이럴 때 씁니다'가 있습니다.

| 탭 | 하는 일 |
|---|---|
| 할 일 | 가입 신청 승인 · 거절(재학생은 **승인하고 구성원 카드 만들기**), 이름이 같은 옛 회원이면 **옛 계정으로 잇기**, 본인 확인 요청(옛 회원 메일 바꾸고 링크 보내기), 탈퇴 처리 |
| 회원 | 찾기 · 거르기, 한 사람 열기: 메일 바꾸기(다른 길로 본인 확인한 방법을 꼭 고름, 기록에 남음) · 구분 · 비밀번호 링크 · 잠금 · CV · **구성원 카드 잇기** |
| 사이트 내용 | 구성원 · 졸업생 · 소식 · 수행연구 · 교과목 더하기 · 고치기 · 빼기 · 순서, 구성원은 사진 올리기와 **졸업생으로 옮기기**. 저장 한 번이 GitHub 판 하나가 되고 1~2분 뒤 공개 화면에 보입니다(진짜 서버 연결 뒤) |
| 관리자 넘기기 | 새 조교에게 넘기기(새 조교가 인증 앱으로 한 번 들어오면 나는 회원이 됨), 두 번째 관리자 두기, 사이트 밖에서 넘길 것 목록 |
| 기록 | 누가 언제 무엇을 했는지, 사이트 내용 고침의 공개 결과와 **되돌리기**(그 뒤에 같은 표를 또 고쳤으면 '고치기 전' 내용을 보여 줌) |

- 관리 화면이 고치는 표 다섯 개의 칸 규칙은 `schema/tables.json` 하나에 있습니다(꼭 적을 칸, 길이, 날짜 모양, 과정 · 학위 낱말 등). 관리 화면 · 서버 도우미 · `build.py`가 모두 이 파일을 읽어 둘이 어긋나지 않습니다. 새 과정(예: 박사후연구원)이 생기면 그 칸의 `choices`에 한 줄 더합니다.
- 구성원 · 졸업생 표의 **'번호'** 칸은 회원 계정과 잇는 뜻 없는 번호입니다(저절로 붙음, 고치지 않음). 졸업생으로 옮겨도 그대로입니다.
- 표 파일을 GitHub에서 직접 고쳐도 됩니다(아래 표). 칸 규칙에 어긋나면 만들기가 몇 번째 줄 어느 칸인지 알리며 멈춥니다. 검사만 하려면 `python3 build.py --check`.

## 이 컴퓨터에서 미리 보기

```bash
python3 build.py --local
python3 -m http.server 8790 --bind 127.0.0.1 --directory _site
```

표를 고치지 않고 다른 색 배치를 잠깐 보려면 `python3 build.py --local --palette 신뢰`(또는 `고급`)로 만든 뒤 브라우저를 새로 고칩니다. 다시 `python3 build.py --local`로 만들면 표에 적힌 배치로 돌아옵니다.

브라우저에서 `http://localhost:8790`을 엽니다. `--local`이면 회원 칸이 **시험용 가짜 로그인**으로 돌아갑니다(이 브라우저 안에만 저장, 바깥으로 아무것도 안 보냄). 가짜 계정은 로그인 화면의 '시험용 가짜 계정 보기'에 있습니다. 미리 보기에서는 로그인하지 않아도 게시판 · 회원 칸이 '시험회원'으로, **관리 화면(`/lab/admin/`)은 '시험관리자'로** 열립니다(10-28, 위쪽 노란 띠의 '관리 화면 보기'). 관리 화면 맨 아래 '시험 자료 처음으로'를 누르면 가입 신청 · 고친 표 · 기록이 처음 상태로 돌아갑니다. 이 브라우저에서 로그아웃하면 그 뒤로는 로그인 화면으로 가므로 로그인 흐름도 시험할 수 있습니다. 공개용으로 만들면(`--local` 없이) 이 기능은 꺼집니다.

- 파이썬 3.12 이상이 필요합니다(다른 설치 없음).
- **화면 폴더 `_site`는 `build.py`만 만들고 손으로 지우지 않습니다.** `build.py`는 폴더째 지우지 않고 바뀐 파일만 고치며, iCloud 동기화에서 빼 두고(이 Mac에만 있음, 다른 Mac에서는 그 Mac에서 한 번 만듦), 다른 대화가 만드는 중이면 끝나기를 기다립니다. 폴더째 지웠다 다시 만들면 iCloud가 지난 판을 `index 2.html` · `about 2` 같은 사본으로 되살립니다(2026-10-27 19개). 시험은 임시 폴더에 만들어 미리 보기를 건드리지 않습니다(`--out <폴더>`).
- 만들 때 이 폴더에서 이름 끝이 ` 2` · ` 3`인 사본이 보이면 그 파일은 쓰지 않고 공개 화면에도 넣지 않은 채 이름을 알립니다. 원본과 비교해 필요한 고침을 원본에 옮긴 뒤 사본은 휴지통으로 옮깁니다(공개 저장소에도 안 올라가게 `.gitignore`에 적음).

## 안전 장치(2_보안검토.md를 따름)

- 모든 화면에 차단 규칙(CSP)을 걸었습니다. 화면 안에 코드를 쓰지 않고, 바깥 주소에서 아무것도 부르지 않습니다(글꼴 · 부품 모두 `assets/` 안). 첫 화면만 지구본 부품이 머리에 넣는 빈 꾸밈 글 두 가지(`''` · `:root{}`)를 지문으로 허용합니다(다른 꾸밈 글은 계속 막힘).
- 바깥 부품의 판 번호와 지문: `assets/vendor/VERSIONS.txt`.
- 회원 글은 마크다운으로 저장하고, 보여 줄 때 DOMPurify로 거릅니다(`assets/js/lab/render.js`).
- 글쓰기 편집기(`assets/js/lab/editor.js`)는 보이는 그대로 쓰고 저장할 때 마크다운으로 바꿉니다. 본문 그림은 우리 사진 칸에 다시 저장한 그림만 `lab:<경로>`로 적고, 바깥 주소 · data: 그림은 보여 줄 때 지웁니다.
- 사진은 올리기 전에 브라우저에서 긴 변 1600px JPEG로 다시 저장해 위치 정보를 지웁니다(`assets/js/lab/upload.js`).
- 회원 칸 권한은 서버 규칙(`supabase/migrations/`)이 막습니다. 화면에서 단추를 숨기는 것은 막는 장치가 아닙니다.
- 글 올리기 설정(2026-11-02, `supabase/migrations/20261102010000_post_settings.sql`): 글쓰기 화면의 '올리기'를 누르면 뜨는 작은 창에서 태그 · 대표 사진 · 공개 범위(회원 전체 · 관리자만) · 댓글 받기 · 위에 고정(관리자만)을 정합니다. 태그 개수 · 길이, 대표 사진이 이 글 사진인지, 고정은 관리자만인지, '관리자만' 글 읽기와 댓글 막기는 서버가 거릅니다.

- 로그인 · 비밀번호 링크 결과 글은 계정이 있든 없든 같습니다(누가 회원인지 드러나지 않게). 가입 신청에서 메일이 이미 있으면 화면은 똑같이 '받았습니다'를 보이고 그 계정으로 비밀번호 링크를 보냅니다. 로그인 없이 보내는 메일은 계정마다 10분에 1번 · 하루 3번, 전체 한 시간 20통까지(`take_mail_quota`).
- 관리 화면의 사이트 내용 고침은 서버 도우미(`supabase/functions/site-content`)가 연구실 조직의 GitHub App으로 표 다섯 개 · 사진 폴더만 고칩니다. 공개 단계(`pages.yml`)의 지킴이(`tools/check_admin_commit.py`)가 그 App이 만든 판이 다른 파일을 건드렸으면 공개를 멈춥니다.
